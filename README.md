# Idle Page

A quiet idle tab: a clock, the date and a month calendar. No framework, no build
step at runtime — just static files.

## Structure

```
index.html              markup
manifest.webmanifest    PWA manifest
sw.js                   service worker (VERSION and ASSETS are generated)
css/
  style.css             hand-written CSS (fonts, shell, type scale)
  tailwind.css          generated by the build, committed
js/
  calendar.js           calendar rendering and interaction
  clock.js              clock and date
fonts/
  Inter.woff2           latin subset, 400
  sf-ui-display-*.woff  Medium and Semibold
icons/
  icon.svg              source artwork for every icon below
  icon-192.png          any
  icon-512.png          any
  icon-maskable-512.png maskable (extra padding)
  apple-touch-icon.png  180px, iOS
  favicon.ico           16/32/48, generated
src/
  tailwind.css          Tailwind source (@import + @source)
scripts/
  build.mjs             icons + Tailwind + cache busting
unused/                 assets kept for reference, nothing loads them
```

## Commands

```bash
npm install        # once
npm run build      # one-off build
npm run watch      # rebuild on every change
```

`npm run build` does three things:

1. Renders `icons/icon.svg` into the PNG icons and `icons/favicon.ico`.
2. Compiles Tailwind into `css/tailwind.css`.
3. Rewrites the `?v=<hash>` cache busters in `index.html` and the
   `VERSION` / `ASSETS` block in `sw.js`.

Only files whose bytes actually change get written, so running the script twice
produces no diff.

### Why the generated parts exist

- **`?v=<hash>`** is a content hash, not a counter. Editing a stylesheet or a
  script changes its URL, so no browser or proxy can serve the old copy.
- **`VERSION`** in `sw.js` hashes every precached file, so any edit also
  invalidates the service worker cache. `ASSETS` is regenerated from
  `scripts/build.mjs`, so moving a file only means editing the list once, there.

Never hand-edit the `?v=` values, `VERSION` or `ASSETS`: the build overwrites
them.

## Notes

- Tailwind classes are compiled ahead of time. After adding a class in the HTML
  or in `js/`, run the build again or the class will not exist.
- The service worker needs `https` or `localhost`. On a LAN address such as
  `http://10.0.0.19:8000` the page works, but offline mode and installation stay
  disabled by the browser.
